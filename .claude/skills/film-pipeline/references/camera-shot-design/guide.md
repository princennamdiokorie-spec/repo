# Постановка камеры

Перевести режиссёрское намерение в понятное движение камеры, затем проверить его в реальной сцене. Хорошая конечная композиция не доказывает правильность пути.

## Сначала определить задачу

- Прочитать актуальный бриф, предоставленную сцену и доступные записи проекта. Прямые новые указания пользователя имеют приоритет; отличать их от старых предложений. Не превращать значения из предыдущего шота в настройки по умолчанию.
- Зафиксировать объект внимания, начало и конец, сторону подхода, смысл движения, длительность, разрешение, fps, объектив/сенсор и паузу в конце. Разделить обязательные условия, предпочтения и неизвестные параметры.
- Для существующей сцены измерить активную камеру, evaluated world transforms, родительские связи, ограничения, анимацию и положение героя. Не подменять рабочую камеру одноимённой или заново построенной сценой.
- Обычные творческие решения принять самостоятельно. Уточнять только противоречие, от которого действительно зависит постановка. Для отсутствующей сцены подготовить предложение и перечень замеров, не выдавать расчётную модель за измерение сцены.

## Разделить путь, наведение и кадрирование

1. Описать движение словами: откуда, куда, через какую область, что раскрывается и где камера останавливается. Указать допустимые повороты и возвраты, если они мотивированы.
2. Задать путь центра камеры в пространстве. Проверить вид сверху и сбоку, порядок контрольных точек, знаки и величины движения. Для прямого подъезда не добавлять боковой возврат ради постоянной экранной координаты героя.
3. Разработать наведение камеры и плавное изменение наклона отдельно, затем проверить их совместно с путём. «Герой в левой трети в финале» не означает «держать его там на каждом кадре».
4. Не считать всякое изменение знака координаты ошибкой: орбита и намеренный обход могут его требовать. Сопоставить возврат с брифом; численный отчёт служит диагностикой, а не автоматическим запретом.
5. При невозможности совместить ограничения показать конкретный конфликт: дистанция, размер бейджа с учётом ракурса, видимость рук, сторона камеры, препятствия. Не исправлять конфликт скрытым зумом, масштабированием героя или перестановкой мебели.

Для сложного надира и вычислений прочитать [references/camera-checks.md](references/camera-checks.md). Не решать недостижимую экранную координату итерациями без проверки существования решения.

## Реализация и проверка

Использовать доступный мост/инструмент Blender; наличие навыка не означает наличие подключения. Сохранить исходную анимацию способом, доступным в этой среде. Менять только нужные свойства. Для API учитывать текущую версию Blender и проверять неизвестные поля через RNA.

Проверять фактическую сцену по кадрам: перемещение, поворот, скорость, объектив, паузу. Просмотреть начало, переходы и самые тесные кадры; после записи проверить сохранённую версию и итоговое видео, если оно создано. Камера в viewport orbit не является ракурсом шота.

Для уже выгруженных измерений использовать:
`python3 scripts/inspect_camera_samples.py samples.json`.
Формат описан в reference. Скрипт не извлекает Blender-сцену и не проверяет изображение, столкновения или готовность шота.

## Границы и результат

Если доступен blender-previz, использовать его для сборки/экспорта, а previz-shot-review — для проверки результата. При отсутствии этих навыков выполнить нужные действия по доступным инструментам, не требовать установки ради названия.

Отдать: замысел движения, интервалы кадров, фактические изменения, результаты проверки с источником и остаточные ограничения. Различать предложение, выполненную правку и подтверждённое сохранение. Тест конверсии Seedance не заменяет проверку самой камеры; уже принятые тесты точности не запускать заново без относящихся к ним новых данных.

# Casting Direction

Treat each character as one persistent identity across screenplay, references, previs, shots, and generated results. Read [deliverables.md](references/deliverables.md) for reusable schemas; read [reference-evaluation.md](references/reference-evaluation.md) when assessing candidates, age versions, or generated takes.

## Authority and intake

1. Locate the current screenplay, character bible, decisions, approved references, storyboard, shot list, camera registry, and visual rules. Record source path, revision, date, and approval state. Current explicit user direction supersedes older material. If sources conflict, cite both; never quietly choose the more attractive image.
2. Mark each assertion LOCKED (approved), PROPOSED (awaiting choice), UNKNOWN (insufficient evidence), or CONFLICT (incompatible sources). Never promote a generated candidate or inferred trait to LOCKED. Continue reversible work while a missing decision is pending.
3. Extract each role's dramatic function and observable identity: age, stature and proportions, face and hair, voice and behavior, wardrobe, recurring props, relationships, and period or scene state. Attach a source to every locked fact. Do not invent ethnicity, disability, backstory, or anatomy to fill gaps.

## Workflow

1. Write a role brief separating mandatory anchors from flexible casting range and temporary state. Describe playable objective, tension, restraint, gesture, and visibility in the planned framing.
2. Compare candidates on the same rubric: identity, performance, age plausibility, cross-angle stability, scale, voice if needed, availability of views, and consent or license for real-person likeness. Cite evidence and tradeoffs; do not give falsely precise subjective scores.
3. For different ages, create one identity map of invariant features and permitted age changes (skin, face fullness, hair, posture, voice, costume). Specify whether one performer, two performers, or generation provides the versions, if decided. Check front, three-quarter, profile, full body, and performance views. Never alter distinctive bone structure without an approved reason.
4. Build a reference hierarchy: approved identity image, neutral multi-angle views, full-body scale, expression set, wardrobe and prop references, and shot frame. Give every asset an ID, provenance, approval state, use, allowed transformation, and limitations. A single portrait cannot establish unseen views; newly generated images remain proposals until approved.
5. Produce age-specific character sheets linked by one character ID and a shot continuity ledger. Separate invariant identity, age or period, scene state, and shot state. Log visible hair, accessories, costume wear, text, hands, prop orientation and handoff, eye line, and entry/exit state where relevant. Compare screenplay chronology and neighboring shots.
6. Write generation handoffs with authoritative reference IDs, positive identity anchors, permitted changes, performance and timed action, framing visibility, and continuity checks. Blender/previs governs camera, geometry, blocking, proportions, and contacts; approved references govern material, color, appearance, and realism. Grey proxies are spatial placeholders. Never suppress a real previs element because prose omitted it. Avoid repeated negative visual tokens.
7. Review first frame, face reveal, turns, contact, and last frame. Classify failures as source conflict, ambiguous brief, model drift, or compositing/continuity error. Correct the smallest affected scope; escalate any change to LOCKED identity or story for approval.

## Handoff

Provide the relevant decision table, character and age sheets, reference manifest, continuity ledger, generation brief, open decisions, and acceptance checks. Include exact versions and source IDs; mark uninspected assets unverified. Deliver only stages requested, without inventing downstream approval. Coordinate with screenplay analysis for motivation, film-continuity for cross-shot review, cinematography for framing, and generation tools for actual assets. This skill owns identity and performance specifications, not screenplay, camera registry, rendering, or final casting approval.
